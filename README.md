# PS5 Combine AIO  ·  by ChrisNWO

**RU** — Портативный «комбайн» для PS5 на C++/Qt 6: упаковка PFS-образов (MkPFS), сборка FPKG (PSVIETHOA fpkg-cli + Sony Publishing Tools), анализ и распаковка `.pkg` / PFS / exFAT. Интерфейс на русском и английском (переключается на лету), тёмная и светлая темы.
**EN** — Portable all-in-one PS5 toolkit in C++/Qt 6: PFS image packing (MkPFS), FPKG building (PSVIETHOA fpkg-cli + Sony Publishing Tools), inspection and extraction of `.pkg` / PFS / exFAT. Russian and English UI (switchable live), dark and light themes.

## Архитектура / Architecture
```
PS5CombineAIO.exe   (Qt 6 GUI, ToolRunner = QProcess + разбор "] 45%" из stdout/stderr)
└─ tools/
   ├─ mkpfs/mkpfs.exe               MkPFS  → PyInstaller --onedir
   ├─ fpkg-cli/fpkg-cli.exe         PSVIETHOA CLI → .NET 10 self-contained
   ├─ ps5aio/ps5aio-helper.exe      (v1.2, необязательно) JSON-CLI поверх библиотек PS5 PKG Tool: метаданные из образов, трофеи, файлы, ремонт exFAT
   └─ sony-sdk/toolchain/…          Sony Publishing Tools (PSVIETHOA_SONY_SDK)
```
Нативно на C++ уже: GUI, i18n, портативные настройки, запуск/отмена/прогресс, чтение `param.json`, проверка `keystone`.
Движки PFS/exFAT/PKG вызываются как проверенные утилиты — это сознательный гибрид (см. «Что не портировано»).

## Сборка / Build (Windows x64)
Нужно на ПК сборки: Qt 6.4+, CMake 3.21+, MSVC или MinGW; для утилит — Python 3.9+ и .NET 10 SDK.
```
:: положите исходники в third_party\MkPFS-main и third_party\PSVIETHOA-FPKG-Builder-main
build.bat -QtDir C:\Qt\6.8.3\llvm-mingw_64
```
Для функций с v1.2 (метаданные из образов, трофеи, Activities, файлы внутри образов, ремонт/правка exFAT, конвертация) положите ещё папку `PS5PKGTool-1.2.0` в `third_party\` — скрипт соберёт `ps5aio-helper`. Без неё всё остальное работает, а Библиотека остаётся в базовом режиме.

Результат: `dist\PS5_Combine_AIO_v1.4.0_win64\` и `.zip`. Папка самодостаточна (Qt DLL + runtime через windeployqt, Python/.NET встроены в утилиты) — копируется на любой ПК с Windows 10/11 x64, установка не нужна. Настройки — `PS5CombineAIO.ini` рядом с exe.

## Новое в v1.3.0 / What's new in 1.3.0
- **Бэкпорт из папки** (страница «Бэкпорт», пункт «Бэкпорт…» в меню Библиотеки): понижение версии SDK и fake-подпись исполняемых файлов дампа — бэкенд [Auto-Backpork](https://github.com/Nazky/Auto-Backpork) (Nazky), собирается в `tools\backpork\backpork-cli.exe` из папки `Auto-Backpork-main` в `third_party`. Режимы: авто / только понижение и подпись / только fake-signed SELF → ELF; SDK-пара по прошивке консоли (1–13; пары 11–13 добавляет сборка, их на консоли не проверяли). **Системные библиотеки fakelib — файлы Sony: программа их не содержит и не ищет, укажите свою папку с ними** (со своей консоли или из своих игр). Результат упаковывается обычным способом; на консоли нужен payload BackPork. У Auto-Backpork нет лицензии — собранный `backpork-cli.exe` не публикуйте в своём релизе без разрешения автора.
- **Только fake-подпись** (режим на странице «Бэкпорт»): рекурсивно превращает ELF дампа в fake-signed SELF без смены SDK — для дампа, снятого на консоли той же прошивки. Работает в копию (проверяется свободное место) или на месте (с подтверждением). Встроенный `bundled\fself` (`make_fself.py` из ps5-make-fself-recursive, BSD-3) собирается в `tools\fself\fself-cli.exe` без сторонних папок.
- **Пары SDK 1–13** (было 1–10): добавлены 11, 12, 13 для консолей на прошивках 11.xx–13.xx. Значения выведены из закономерности таблицы Auto-Backpork и **на консоли не проверены** — в списке помечены «экспериментально». Подпись «PS4 …» из списка убрана.
- **Эмулятор AMPR:** в «Настройках» — автоматическое добавление без вопроса и версия по умолчанию, а также «всегда добавлять» (если проверка не срабатывает); в «Обзоре» дампа строка про AMPR показывается всегда (что найдено в `eboot.bin`, какие модули в `fakelib`). Для чистого exFAT индекс AMPR пересоздаётся отдельным шагом после упаковки.
- **exFAT:** выбор размера кластера для режима «чистый exFAT»; в «Сверить образы…» новая вкладка «Структура exFAT» (кластер, сектор, FAT, флаги тома…) и вывод об отличиях.
- **Проверки перед упаковкой:** папка `decrypted` (остаётся после Dump Runner) — предложение перенести её рядом с игрой.
- **Библиотека:** названия по всем языкам из `param.json`, «реальный минимум прошивки» (по `requiredSystemSoftwareVersion` и SDK) и предел загрузчика, размер дампа считается самой программой.
- **Интерфейс:** заметные чекбоксы везде (рамка, заливка, галочка), в т.ч. в списках.
- Python-утилиты запускаются в UTF-8 (`PYTHONUTF8=1`).
- Сборка: шаги `[5/6] backpork-cli` и `[6/6] fself-cli`; ключи `-SkipBackpork`, `-SkipFself`.

## Если сборка не проходит / Troubleshooting
- Лог каждой сборки: `logs\build-ГГГГММДД-ЧЧММСС.log` — присылайте его целиком.
- Компилятор выбирается автоматически под Qt: `llvm-mingw_64` → clang из `Qt\Tools\llvm-mingw*`, `mingw_64` → gcc из `Qt\Tools\mingw*`, `msvc*` → Visual Studio. Смешивать комплекты нельзя (ошибки линковки `std::function` / `__p___argc`).
- Сменили Qt или компилятор — папка `build\gui` пересоздаётся сама (или ключ `-Clean`).

## Исправления «болячек» оригинала / Fixes to upstream behaviour
**Прогресс распаковки/сборки «замирал» (v1.0.1).** В `fpkg-cli` при перенаправленном выводе (а GUI читает именно pipe):
- `pkg-extract` печатал строку прогресса только при смене десятка процентов — на пакете 46 ГБ это минуты тишины;
- прогресс сборки печатался только при `PhasePercent % 10 == 0`, а `PhasePercent` — `double`, т.е. почти никогда.

Теперь строка выводится раз в секунду при изменении процента. Исправление накладывается скриптом `build-tools.ps1` на **рабочую копию** исходников (`build\tools-work\psv`), ваши оригинальные папки не меняются; если исходник другой версии и фрагмент не найден — патч не применяется, в логе будет строка `! патч не применён`.
Кроме того, GUI показывает «Прошло mm:ss» и, если утилита молчит > 15 с, пишет об этом — программа больше не выглядит зависшей.

*Заметка:* размер папки в Проводнике во время распаковки — не показатель прогресса (файлы могут создаваться заранее нужного размера). Ориентируйтесь на счётчик файлов/байт в программе.

## Остановка утилит при закрытии (v1.0.2)
Раньше при закрытии окна во время распаковки утилита могла остаться жить в фоне и продолжать писать на диск. Теперь три уровня защиты:
1. **Подтверждение.** Закрытие во время задачи спрашивает «Остановить и выйти?»; при согласии программа убивает утилиту **вместе со всеми её дочерними процессами** и ждёт, пока они реально завершатся (до 8 с).
2. **Любой выход.** Тот же код выполняется и при выходе не через крестик (`aboutToQuit`). Кнопка «Отмена» работает так же.
3. **Job Object Windows (`KILL_ON_JOB_CLOSE`).** Каждая утилита запускается внутри задания ОС: если программа аварийно упала или её сняли через Диспетчер задач, Windows сама убивает утилиту и всех потомков. Если поместить процесс в задание не удалось — запасной путь через `taskkill /T /F`.

Что остаётся: файл, который писался в момент остановки, будет неполным — его можно удалить вручную. Единственное, что нельзя перехватить, — отключение питания/BSOD (но после них процессов и так нет).

## Образ не запускается на PS5 — чек-лист
1. Корень образа — папка, где лежат `eboot.bin` и `sce_sys\param.json` (программа теперь проверяет это сама).
2. Режим «Папка → чистый PFS (.ffpfs)» с включённым сжатием — для опытных; по умолчанию используйте «Папка → .ffpfsc».
3. Профиль PFS — `PS5` (не `PS4`).
4. Сравните «Треб. прошивка» игры с прошивкой консоли (Библиотека).
5. Убедитесь, что ваш загрузчик/монтировщик поддерживает именно этот контейнер (`.ffpfsc` / `.exfat` / `.ffpkg`).
6. Оставьте включённой проверку после упаковки — лог проверки нужен для диагностики.

**Важно:** ни PS5 PKG Tool, ни MkPFS, ни этот комбайн не гарантируют запуск на реальной консоли; образы проверяются на ПК.

## Полная сборка: что положить в `third_party` / What to put in `third_party`
См. `third_party\PUT_SOURCES_HERE.txt`. Кратко:

| Папка | Нужна для | Обязательна |
|---|---|---|
| `MkPFS-main` | упаковка образов | да |
| `PSVIETHOA-FPKG-Builder-main` | сборка FPKG | да |
| `PS5PKGTool-1.2.0` | метаданные образов, трофеи, файлы, ремонт/правка, сверка | рекомендуется |
| `Auto-Backpork-main` | «Бэкпорт»: авто и понижение SDK | нет (нет лицензии у проекта) |

Уже внутри проекта: `bundled\ampr_emu` (эмулятор AMPR) и `bundled\fself` (fake-подпись). `ps5-app-dumper` для сборки не нужен: это payload, который работает на консоли и снимает дамп на USB — источник дампов для программы.

## Как это складывается / Workflow
1. Дамп игры со своей консоли (например, payload ps5-app-dumper — внешняя утилита, на консоли).
2. Библиотека → «Бэкпорт…» (понижение SDK + подпись + ваши fakelib) либо «Только fake-подпись» (та же прошивка).
3. «Упаковка PFS» → образ; проверка «Сверить образы…» с рабочим образом при проблемах.

Подробный порядок «дамп → fake-подпись → запуск» (в т.ч. ShadowMountPlus, формат FFPKG, права `/data`, сброс ShadowMountPlus) описан в руководстве Alex Free: https://alex-free.github.io/ps5-game-backups-guide/ . Из него учтено: Dump Runner переносит исходные файлы в папку `decrypted` (программа предложит убрать её из папки перед упаковкой); для образа FFPKG (UFS2) используйте «Конвертировать → FFPKG».
